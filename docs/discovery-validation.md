# Discovery 验证记录

本轮日期：2026-10-22。设计依据见[架构与来源研究](discovery-design.md)，接口及限制见[适配器指南](discovery-adapters.md)。常规测试使用合成文件、假网络响应和隔离项目，不依赖实时服务。

## 证据分层

- 自动化程序测试：解析、来源契约、网络/缓存、引擎决策和原有验收工具分别运行；PASS、FAIL、SKIP 均由实际 runner 记录。
- 官方文档研究：用于确定API、目录和授权规则，不证明当前账号连通或服务可用。
- 有界在线检查：只发送公共关键词，不启用凭据，不安装 Skill 或运行其脚本；每个来源单独报告实际结果。
- 全新上下文试用：用于观察宿主如何使用发现结果；不等同于完整行为认证、成功率或安全证明。

## 程序检查覆盖

| 要求 | 实际检查 |
| --- | --- |
| 六类来源正常路径 | 来源契约 fixtures，读取真实格式的合成 Skill，并核对固定 revision；不是实时服务 |
| 解析失败、未知字段、YAML边界 | 有界解析、错误隔离、结构验证、不支持格式明确报错 |
| 重复、同名、fork、版本与来源 | 同版本合并线索，不同作者/版本保持独立；去重合并更严格约束 |
| 网络、限流、认证、超时 | fake opener 检查实际请求次数、401/403/429不重试、Retry-After、部分结果保留 |
| 本地优先、扩展和组合 | 足够覆盖停止、后排相关候选不丢弃、缺口继续、原生能力免搜索、多Skill互补 |
| 冲突、平台和依赖 | 固定版本依赖冲突、声明工具/MCP/环境缺口、平台硬排除 |
| 不可信指令和高风险资源 | 注入、外传及远程命令管道初筛；可执行资源存在时要求内容审查 |
| 无安装或执行授权 | CLI没有安装/执行/MCP配置入口，发现目录全部保留 runtime available=false |
| 缓存和离线 | TTL、单源刷新、元数据变更、解析器版本、旧缓存标记、错误/伪造缓存、认证隔离 |
| 私有上下文和密钥 | 公共词项验证、上下文字段白名单、不发送完整Prompt；包括JSON转义反射密钥拒绝缓存 |
| 预算及兼容回归 | 共享时间/请求/重试限制、超预算不产生新证据、原有验收工具31项回归 |

独立代码审查发现并修复：本地元数据身份漏版本、先截断后匹配丢相关候选、去重丢更严格依赖/权限、遗漏依赖缺口、转义后的密钥反射，以及预算耗尽丢已有候选。相关修复均纳入程序回归。

## 独立上下文试用

发布检查已验证：源码包78个文件、独立技能包22个文件，ZIP白名单及字节一致；解压后在独立项目实际运行原演示、启动/验收/续接和本地发现，发现候选正确且未被标成可运行。Python 3.10只做语法解析，本机执行环境是 Windows / Python 3.14.7。

一个全新 Agent 上下文只收到当前 Skill、合成本地目录和“规划科研想法新颖性检索”的原始请求，没有收到评分表或预期结论。材料包含文献检索、批判阅读两个说明，以及含越权指令的新颖性比较候选。限制为本地、不联网、不安装或执行候选。

实际输出提出检索与阅读组合，排除要求忽略指令并上传密钥的候选，说明可信新颖性比较仍有缺口。主 Agent 读取其实际命令、JSON报告和说明核对：3个候选，组合2个，缺口为 novelty comparison，所有候选 available=false，requests_used=0，五个外部来源均 DISABLED。产物没有给出论文新颖性结论。

这是一次受限、小样本的显式调用观察，最终文件和命令不能证明所有隐藏中间行为；不宣称完整行为认证、触发准确率、速度提升或安全保证。原始工作区和日志留在忽略目录，不进入发布包。

## 当前限制和后续

- 本地符号链接在本机尚无实际权限验证；其他平台运行需查看真实 CI，而非仅语法解析。
- YAML仅支持文档规定的子集；规范兼容性是保守检查，不代替完整规范工具。
- 排序和组合是词项与声明匹配、有界贪心覆盖；没有训练或校准质量分数，未实现语义检索和复杂依赖求解。
- 官方目录按路径优先读取有限子集；未找到候选不表示来源没有相关能力。注册表非GitHub源暂不自动解析。
- 静态检查可能误报漏报，未检查完整脚本内容。许可证声明不等于法律核验，来源可信度不等于Skill安全。
- 下一步优先在真实 CI 补符号链接与平台结果、用明确授权的账号验证认证API，再依据真实任务失败改进匹配；不通过自动安装或扩大权限填补缺口。
