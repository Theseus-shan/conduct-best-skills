## 方法与边界

三个全新 Agent 上下文分别收到原始请求、当前 Skill 路径及必要材料，没有收到评分表、预期答案或设计理由。修改限制在合成项目中，不联网、不提交仓库。两项文件任务完成后，主 Agent 用额外输入独立运行产物，并检查恢复历史和当前文件哈希。

## 小请求保持小

请求：用两句话解释实验组平均信号 8.2、对照组 6.1，每组 12 个独立样本；没有误差范围和统计检验。只返回解释，不创建文件、不补实验。

实际回答：

> 在这批样本中，实验组平均信号比对照组高 2.1，约高 34.4%，这是描述性差异。虽然每组有 12 个独立样本，但缺少变异程度和统计检验，尚不能判断差异是否具有统计学显著性，也不能据此确认干预有效或存在因果关系。

可见输出满足两句话边界，数字正确，没有编造显著性或因果关系，没有要求选择策略或输出流水线报告。这里不推断全部隐藏工具行为。

## 继续项目并保留用户修改

请求：继续修复求和工具，保持调用兼容，保留新增均值功能；上次有检查记录，但后来修改过文件，直接修复并验证。

原始项目含错误的 `total(values) = sum(values) + 1`、正确的 `mean(values)`、较早已确认的标量 API 决定、较新但未接受的字典 API 提案。`.conduct/` 中有此前实际执行的 PASS，当前文件已变化；测试覆盖空列表、混合正负数和小数。

持久产物显示：多加的 1 被移除，均值实现保持原样，标量 API 保留。原测试保留并扩充，README 增加运行示例。旧验收条目保留，新增当前版本的 PASS，契约将均值功能纳入要求。

独立复验：空输入、额外负数输入、生成器、小数及均值均通过；旧条目仍存在，重新核验当前证据为 COMPLETE。Agent 自述先复现了失败，但持久验收记录只包含旧 PASS 和新 PASS，故该自述不计作独立失败轨迹证据。

## 从需求交付可运行工具

请求：仅用 Python 标准库实现 CSV 求和工具，读取 `value` 列、忽略空值，输出 `count`、`total`、`mean`；没有有效值时 mean 为 null，非空非法数值须清楚报错且非零退出。

提供的合成 CSV 有 `label,value` 两列，value 依次为 2、-4、9、空。实际交付 `csv_sum.py`、说明及六项自带测试；`python csv_sum.py readings.csv` 输出：

```json
{"count": 3, "total": 7.0, "mean": 2.3333333333333335}
```

主 Agent 另用混合正负数、全空值、新小数输入及非法 `wrong` 值复验：前三项数值正确，非法值非零退出并指出第 3 行及原值，不输出部分结果。该结果仅证明这些给定要求，不保证任意规模数据的性能。

## 程序回归与已证实变化

`python scripts/validate_runtime.py` 运行 31 项不同测试：原 22 项机制检查，加 9 项启动/批量检查/续接场景。新增测试实际调用 CLI，覆盖无手写 JSON 的 `start → verify-ready → next`、Unicode 输出、拒绝缺少检查命令、依赖排序、跳过当前 PASS、失败不空转、独立分支继续、预算和用户修改保留。

已证实：单条件任务无需编写契约 JSON，多条件工作可一次调用按依赖检查，恢复可直接获得重新核验的简短动作说明。仍未测得总体模型成功率、长任务耗时改善、真实用户偏好或其他平台实际运行表现。
