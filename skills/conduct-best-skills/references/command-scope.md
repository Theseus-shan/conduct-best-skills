# 各能力入口的共同约定

先确定用户正在处理的工作空间根目录，读取适用项目指令和[项目偏好](preferences.md)。不要把 Skill 安装目录或总控开发仓库误当成用户工作空间。

- 每个入口是有边界的工作模式；只加载本次需要的参考。用户只要求计划、发现、验证或交付时，不因为共享总控规范而实施其他阶段。
- 项目默认 + 当前任务覆盖 + 当前 prompt，按这一顺序覆盖。开始工作、切换任务类型、用户修改偏好后重新解析；命中的可用 Skill 默认加载并应用，而不是仅提高推荐分数。
- 指令来源、权限、专业适配和必要验收仍是硬条件。偏好不能安装缺失能力、替用户授权外部操作、自动委派或省掉真实证据。
- 默认单 Agent。明确区分配置、选中、加载、实际调用和验证。未知写入先查状态；保留用户新增内容。
- 命令后没有任务正文时复用当前明确目标；没有可识别目标则简短说明输入需求，不能凭命令名编造项目。
- 相对路径从实际加载的 Skill 文件位置解析；本地工具在共享核心 `conduct-best-skills/scripts/` 中，不能假定用户项目也有这些脚本。

可视化展示偏好解析结果，不证明能力已调用。每次交付遵守当前命令边界，给出对应成果、证据和必要限制。

已启用项目追踪时遵循[工作台规范](workbench.md)，按工作/任务记录实际能力使用与结果。复盘入口只读现有记录及必要证据；工作台入口可打开已登记项目视图，不自动扫描其他项目。
