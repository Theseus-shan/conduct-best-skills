# 能力命令路由

独立入口采用 `$conduct-<命令> <任务>`；核心也接受 `$conduct-best-skills <命令> <任务>`。以下是 Agent 的范围契约，不是 shell 子命令注册表。核心路由直接读取本目录规范，不依赖独立入口已安装。

先遵守[共享调用规则](command-scope.md)与[工作空间偏好](preferences.md)。显式命令优先于自然语言自动路径，但用户正文中更具体的范围限制仍优先。

| 命令 | 能力 | 按需读取 | 交付与停止边界 |
| --- | --- | --- | --- |
| `context` | 上下文核查 | [规范](stage-1-context.md) | 交付可信上下文、缺口和下一步；不修改业务产物。 |
| `goals` | 目标澄清 | [规范](stage-2-goals.md) | 交付任务契约与未决选择；不把建议当成已接受目标。 |
| `plan` | 规划编排 | [规范](stage-3-planning.md) | 交付可执行计划、能力缺口与验收安排；不自动进入实现。 |
| `discover` | 能力发现 | [规范](discovery.md) | 交付候选来源、适用性、依赖和缺口；发现不等于已加载、可运行或已授权。 |
| `build` | 实现需求 | [规范](workflows.md) | 在原范围内完成实现和必要修复，交付当前版本成果与实际验证。 |
| `improve` | 优化项目 | [规范](workflows.md) | 交付改动、实测改善和剩余缺口；不把自评分或新增代码量当作改善。 |
| `resume` | 恢复工作 | [规范](workflows.md) | 从最早必要未完成处继续并验证；未知写入先核对，不能重放副作用或覆盖新修改。 |
| `verify` | 证据验证 | [规范](stage-5-verification.md) | 交付已通过、失败、未覆盖或过期的证据及问题定位；不更改被检成果、不降低验收。 |
| `refine` | 定向修正 | [规范](stage-6-refinement.md) | 交付修复与重新验证证据；持续无进展时停止对应重试，范围外建议不自动实施。 |
| `deliver` | 整理交付 | [规范](stage-7-delivery.md) | 交付成果入口和准确完成状态；不自动重建产物、发布或发送给他人。 |
| `preferences` | 工作偏好 | [规范](preferences.md) | 交付可编辑文件和本次生效范围；临时 prompt 覆盖不写回，其他项目不继承。 |
| `reflect` | 项目复盘 | [规范](workbench.md) | 按任务核查实际调用、结果与用户反馈，提出改进建议，不自动改默认。 |
| `workbench` | 可视工作台 | [规范](workbench.md) | 打开实际工作图、产物与待办，以及调用星图；按授权同步 Codex 项目和近期聊天快照，不扫描无关目录。 |

`build`、`improve`、`resume` 分别读取 workflows.md 中实现、优化、继续部分。`context`、`goals`、`plan`、`discover`、`verify`、`deliver` 不自行扩展到实现或修复。组合请求按用户给定顺序与依赖执行，不把每个入口当作重新开始的新项目。`preferences` 支持查看、修改和打开动态框架图。
