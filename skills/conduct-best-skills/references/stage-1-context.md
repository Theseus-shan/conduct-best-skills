# Stage 1 · Context Initialization · v1.0

输入为用户要求、适用规则、工作区、执行偏好、可访问的项目来源与历史、能力元数据。只建立信息基础，不在本阶段开展正式修改或大型实验。

## 执行

1. 识别项目与专题，读取适用 AGENTS.md。执行策略优先采用当前请求，再采用用户主动保存的默认值；两者均无则询问，不自行设为 Balanced。项目身份只有在影响来源选择且无法确定时才询问。
2. 从相关项目文件、用户关联的知识库范围、转交的历史摘要及获准仓库发现来源。不要扫描全部账户、无关项目或凭据。
3. 进行必要的来源协商：已有授权和关联可按需读取；新增来源或扩大范围时检查所需授权。关键资料不可访问时标记 Unavailable 并请求补充；可选缺口不阻塞。
4. 选择加载深度：L1 基础规则与必要材料；L2 加上相关依赖、项目文档和决策；L3 深入核查关键证据、假设与版本。与后续规划深度分别管理。
5. 对重要来源记录 provenance、version、validity、decision_status、security、scope。区分文件修改时间、决策生效时间和读取时间；仅日期更新不能覆盖旧决策。决策状态为 Proposed / Confirmed / Superseded / Rejected / Uncertain。
6. 低等级冲突有证据则消解；中等级记录分歧、影响和不确定性；无法凭证据消解且影响重要决策的高等级冲突，说明双方来源、影响及所需裁决，暂停相关判断。
7. 输出项目与专题、原始要求、有效策略、已读来源及版本、决策、事实与假设、缺口与冲突、充分性状态。

## 质量门

核对身份、策略、核心材料、重大冲突、重要来源有效性，以及缺口是否会误导下一阶段。

- READY：信息足以继续。
- READY_WITH_GAPS：非阻塞缺口已明确，携带后续检查项继续。
- BLOCKED：关键来源、策略或裁决缺失；不绕过阻塞。

Project Context Profile 保存用户主动关联的项目、专题、来源范围与确认决策；Task Context State 保存本次已读证据和缺口。两者不混用。一次性来源和任务推断不自动成为长期记忆，撤销来源不再自动读取，缓存不冒充最新核查。

后续发现过时资料、新关键依赖、来源撤销、目标或范围变化时，仅重新核查受影响上下文。不假定可以访问用户全部 ChatGPT 历史。
