# Stage 5 · Verification & Quality Assurance · v1.0

用当前有效契约验证实际产物，建立 Requirement → Artifact/version → Method → Evidence → Result。不得将计划中的检查、工具退出成功或模型自评当作成果验收。

使用新发现能力时，记录其真实来源、revision、本次输入与产物证据。静态风险扫描、规范格式或社区收录都不代替当前任务验收；“能找到”与“能胜任”分别判断。

## 验证方法

按风险检查完整性、正确性、合规性、鲁棒性和证据质量。选用真正能检验要求的方法：

- 软件：适用的构建、语法、单元/集成/回归测试及边界输入。
- 数学与控制：定义和假设、推导、不等式、定理适用条件、收敛时间界、约束/奇异性及反例。仿真不能替代证明。
- 实验：配置、数据、基线公平性、种子、复现条件、统计和结论一致性。
- 文献：来源真实性、引用、原文支持范围及新颖性证据。
- 文档和图表：内容、格式与必要的实际打开或渲染检查。

高风险优先可重复测试、原始证据、独立方法和反例检查；获准时可交叉审查。多个 Agent 一致不等于事实证据，分歧按证据处理。

每条关键结论包含条件 ID、产物版本、方法、实际结果、证据位置与不确定性。验证期间版本变化使受影响结论失效，应重验。环境缺失标记 UNTESTED 或 INCONCLUSIVE；不要捏造日志、仿真或引用。

## 验收与缺陷

逐项状态为 PASS / FAIL / UNTESTED / INCONCLUSIVE / NOT_APPLICABLE。NOT_APPLICABLE 需要说明契约内确实不适用的依据，不能用来绕过必需条件。

缺陷记录 ID、Critical/Major/Minor/Advisory 严重性、受影响条件、证据、复现、可能根因和处理状态。

阶段状态：

- VERIFIED：全部适用 Mandatory 条件有足够证据支持；无遗留必要失败或未知。
- FAILED：存在明确证据证明必要条件失败。
- PARTIALLY_VERIFIED：部分通过，仍有未满足或未验证必要条件；若有明确必要失败，优先报告 FAILED 并列出通过部分。
- INCONCLUSIVE：关键证据不足，无法可靠判断。

严格反证可以满足“审查命题”的任务，但命题真伪与任务完成分别说明；证据不足不能当作命题已被否定。通过转阶段 7；其余有可行修正路线转阶段 6，无路线则准确交付部分或不确定结果。
