# Stage 6 · Refinement & Optimization · v1.0

输入为验证矩阵、缺陷、契约、当前产物及版本、执行记录和剩余预算。目标是缩小剩余验收差距，不无条件重做或追求额外功能。

1. 按证据定位根因：上下文 → 阶段 1；目标或验收定义 → 阶段 2；能力与计划 → 阶段 3；代码、操作或产物 → 阶段 4；验证方法错误 → 阶段 5。
2. 优先处理安全/数据/权限、核心正确性、验收阻塞、可靠性，再处理一般质量与可选增强。结合依赖和修复风险排序。
3. 比较修正的根因覆盖、授权、影响、新风险、成本和可验证性，采用最小充分修正。局部补丁掩盖系统问题时允许考虑结构性修正，但先核对范围授权。
4. 保存缺陷、方案、实际变更、影响文件、前后版本和重验要求；保留仍有效的成果。
5. 改动后回阶段 5，既检查原缺陷又检查受影响的已通过条件。基础模型或路线改变时扩大必要回归范围。

质量迭代预算独立于执行恢复预算，同时受任务总预算约束。按任务选择有限轮数、资源与连续无进展上限，不统一要求三轮或五轮，不擅自突破用户上限。

进展是消除缺陷、通过条件、明确根因、获得有效证据或减少关键不确定性；仅反复改动不算进展。

停止条件：全部必要条件通过；可用恢复/修正预算耗尽；持续无进展；根本不可行；继续需要重大范围、目标、资源或授权决定；用户取消。仅受影响工作等待必要决定；可选增强不得扩展正式任务。

输出 Refinement Record、变更影响、重验要求、剩余问题和停止原因。状态：REFINED_READY_FOR_VERIFICATION / REFINEMENT_PARTIAL / REFINEMENT_BLOCKED / REFINEMENT_LIMIT_REACHED / REFINEMENT_NOT_REQUIRED。修正完成不能直接跳为 VERIFIED。
