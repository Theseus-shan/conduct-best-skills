# Stage 7 · Delivery & Continuous Learning · v1.0

对照契约逐项交付成果、证据和剩余问题。简单任务用短汇报，不强制创建报告文件。

交付前检查实际文件/资源存在、路径可用、版本与验证一致、无遗漏以及无未经授权的额外内容。不要构造不存在的文件链接，不将拟运行写为已运行。

回答：实际完成什么、成果在哪里、哪些要求验证通过、哪些仍未满足、是否有需要用户决定的事项。按需附复现或恢复步骤、关键变更及其影响。

采用外部发现能力时，按需附所用 Skill/Plugin、来源、不可变版本、实际调用及验证范围；未选择的搜索结果不冒充已使用能力。陈旧缓存、受限来源与尚未核查的依赖在相关结论旁说明。

分别判断 Task Completion、Artifact Delivery、Validation Status，再给出准确状态：

| 状态 | 使用条件 |
| --- | --- |
| DELIVERED_VERIFIED | 必要目标完成、必要验收通过、实际成果已交付 |
| DELIVERED_PARTIAL | 有有效成果但仍缺必要要求 |
| DELIVERED_INCONCLUSIVE | 分析已交付但关键结论证据不足 |
| DELIVERED_BLOCKED | 存在明确阻塞，移交成果及阻塞依据 |
| CANCELLED_WITH_HANDOFF | 用户取消，交付可保留成果及已核对的停止状态 |

审查命题的严格反例可能构成已验证交付；不得混淆命题不成立与任务失败。

只有已有保存授权时才按 [learning.md](learning.md) 更新统计与偏好。区分能力参与、操作成功和最终验收，不将联合成果无依据归功于所有 Skill。不自动修改全局 AGENTS.md 或已安装技能。

Delivery Gate：契约一致、产物可定位、证据真实、问题披露、无未授权发布/传输、学习更新符合保存范围、完成状态准确。交付阶段结束不意味着所有任务都成功。
