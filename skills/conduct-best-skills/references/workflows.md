# 实现、优化与继续

只执行与当前请求有关的一条路径。七阶段参考用于解决遇到的问题，不是开工前的阅读清单。三条路径共享同一原则：用户指定的成果类型、已有决定和验收不能被流程替换。

## 实现：先跑通，再扩展

适用：“做一个能用的……”“把这个功能实现”。

1. 找到真实用户入口、最小代表输入和期望输出。已有项目先复用结构与可用组件。记录影响接口/含义的未决假设；不记录变量名等普通实现细节。
2. 先贯通最小完整路径，例如命令行读入一份样例并输出真实报告、网页实际提交并显示结果、数据流程从原始数据生成一张可核对图。初版可以简陋，但承诺的核心路径不能靠固定假数据冒充；必要占位明确标注且不计验收通过。
3. 按用户价值和依赖顺序添加功能。每项确认：服务哪个要求、能看到什么变化、用什么输入验证。保留前面已通过的能力，别在末尾才第一次运行。
4. 交付时提供一条实际运行过的使用方法或可打开文件；说明覆盖哪些输入与边界。检查方法与要求对应，不能只检查文件存在。

示例：用户要批量生成报告。先用一份真实格式样例验证计算和报告内容，再处理批量、空输入和错误提示；不能先美化界面而计算仍是占位。

## 优化：先找痛点，再证明改善

适用：“优化这个项目”“做得更好用”“完善效果”。

先检查现有成果和使用路径，找出最影响目标的瓶颈。把已观察到的问题、推测和建议分开；能从当前材料判断时直接推进，不把模糊请求转成一轮泛泛访谈。

开始修改前保留一个够用的基线：

| 目标 | 可用的比较依据 | 不能替代它的东西 |
| --- | --- | --- |
| 修复正确性 | 相同输入的失败/修复后结果及边界检查 | 修改行数 |
| 减少操作负担 | 完成同一任务所需步骤、重复输入或澄清次数 | 加入更多选项 |
| 提高速度/资源效率 | 同环境、同规模、同输入的实际测量，必要时重复 | 感觉更快或一次自评分 |
| 改善文档/图表 | 真实打开或渲染、信息完整性、目标读者能否定位关键内容 | 编译返回 0 |
| 提升科学论证 | 主张与原始结果/引用对应，适用条件与反例核查 | 语言更肯定或审稿分数上涨 |

选一个最高价值且可验证的改进先落地，再处理其他必要缺口。保留兼容性、用户新增内容和有效成果。方法无效时改变方法，不改成功标准。

用最小记录支撑迭代：问题与依据 → 本次变化 → 实际检查/观察 → 改善、无改善或未知 → 下一步。复用现有任务记录，不另建一套目录。开始重复修正前确定本次有限尝试上限；同一失败没有新证据时转向，预算耗尽则交付已取得成果和明确缺口。

“亮眼”优先体现在完整可用路径、明显减少的繁琐步骤、能展示的效果证据。可提出增强，但不为显得强大而额外接服务、换架构或改用户目标。没有用户研究时可以说减少了已测步骤，不能说更多用户喜欢它。

## 继续：从可信进度向前

适用：“继续”“接着上次”“中断后恢复”。

1. 读取当前请求、最小记录和当前文件，确认用户后续修改优先。没有记录时从产物、检查和明确决定重建续接点；不得假装记得不可访问历史。
2. 区分已执行、已验证、证据过期、尚未做与结果未知。读取记录不是重新执行授权；已有授权有效则直接继续，不重复批准同一工作。
3. 有 `.conduct/` 时先 `next`/`status`；只有实际匹配当前文件的证据才可复用。若旧契约与新请求冲突，先修订相应契约及依据，不重新初始化来清掉历史。
4. 未知外部操作先查询结果，保留同一身份；不因超时重建。用户文件不能被旧快照覆盖。依赖方等待，独立工作继续。
5. 在最早的必要未完成或需重验处继续，简短说明恢复了什么。结束时更新真实下一步，而不是让后续 Agent 从头猜。

## 专业能力交接

发现 Skill 后先读其描述确认匹配，只有选中才加载正文；主任务不会因为“可用技能很多”自动变成多个 Agent 或大流程。

交接只需：输入来源与范围、要交付的对象、不可改变的事实/接口、证据要求、已有产物位置。输出先核对这些条件，再整合到主任务。例如已有稳定来源映射的 reader 可作为精读输入，不需要再做全篇翻译；已有实验结果先审证据，不默认重跑实验。

需要独立核查且宿主支持、当前授权允许时才委派。给核查者原始要求和实际材料，不把期望结论写进任务。记录审查实际覆盖范围；同模型、异模型或人工评审都不能仅凭身份保证正确，科学断言仍需要原始证据。无法独立核查时明确使用了哪些其他检查，不把自审称为独立评审。

## 交付样式

默认匹配用户语言，先给结果，再给使用入口、验证依据和必要限制。无需显示内部状态码或每一步的流程术语。仅在用户需要机器读取/交接时附完整记录。

任务简报是工作记忆，不是验收结论。命令检查、专业审查、使用体验对比各有证据范围；没有覆盖的维度写未知，不自动推广。
